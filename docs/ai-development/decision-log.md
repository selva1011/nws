## 2026-11-19 — White seating showroom catalogue (supersedes the dark theme)

| Field | Value |
|---|---|
| **Status** | Implemented |
| **Problem** | The user replaced the dark direction with a white showroom and supplied a reference screenshot for catalogue density, base alignment, white space and category grouping. The previous catalogue (search, sort, grid/table, eight per page, three-model comparison) did not match. |
| **Decision** | White/charcoal/yellow tokens (same role names, new values plus gold/selected/focus). Rebuild `/products` as a shallow hero + grouped grid with a link-based URL category selector; fixed column counts (2→8) shared by every section. Whole-tile links with a reserved hover/focus reveal of the verified catalogue style. Framed display copies of every photo (`public/product-display/`, generated by `scripts/frame-product-photos.swift`) so chair bases align; originals untouched. Detail page gains a back-to-catalogue link, gallery swipe/arrows/buttons for multi-photo products, Call with the phone number and a spec table showing only present fields. |
| **Alternatives considered** | (1) Per-image CSS framing from stored bounding boxes: rejected; more runtime complexity and larger image requests for the same result. (2) Keep comparison/search/sort: removed as part of "replace the browsing UX"; the quote route still accepts up to three slugs if a shortlist returns. (3) `history.back()` for the detail back link: rejected; unreliable when the previous entry is not the catalogue. A normal link to the stored filter plus a tile anchor is predictable, and browser Back still restores scroll. (4) White photo stage: rejected; tiles would lose a consistent stage shape on the white canvas. |
| **Reasoning** | Matches the requested density and alignment with real assets and verified data only; keeps the URL as the single source of filter state. |
| **Consequences** | New or replaced photos need the framing script re-run. Hover detail shows "View details" for models without a distinguishing verified style. The two Flip Training Chairs display as "Flip Training Chair (With Pad/Without Pad)". Catalogue meta descriptions and one home FAQ no longer mention comparison. |
| **Affected areas** | `app/globals.css`, `app/layout.tsx`, `app/products/*` (new `CatalogueView.tsx`, `[slug]/BackToCatalogue.tsx`), `components/ProductCard.tsx`, `Header.tsx`, `Footer.tsx`, `SeatFinder.tsx`, home/about/quote/services/contact form styling, `public/product-display/`, `scripts/frame-product-photos.swift`, docs |
| **Approver** | User request in the 2026-11-19 session |

## 2026-11-19 — Dark theme with yellow accents; logo artwork removed (superseded the same day)

| Field | Value |
|---|---|
| **Status** | Implemented |
| **Problem** | The user requested a bold dark theme with distinct yellow accents across the public site, removal of the NWS logo artwork, and matching documentation. |
| **Decision** | Replace the plum/lavender tokens with role-based dark tokens (page/surface/raised, text/muted, accent/hover/link, control/border/error, image surface). Render the brand name as a text link in header and footer; drop the logo URL from Organization JSON-LD. Present all product photos unmodified on a white image surface. Reserve yellow for actions, links, focus and selection, with non-colour cues for every state. |
| **Alternatives considered** | (1) Keep old token names with new values — rejected; names like `light-base` would describe dark colours. (2) Multiply-blend photos onto dark or tinted stages — rejected; the photos have opaque white backgrounds and mostly black chairs, so blending hides chairs or shifts colour. (3) Yellow fill for selected chips/pages — rejected so a yellow fill always means a primary action. (4) Delete `public/logo.png` or replace the favicon — not requested; the favicon and social image do not use the logo. |
| **Reasoning** | Role names keep future use self-explanatory; the white image surface is the only way to keep the supplied photos true to colour and readable on a near-black page. |
| **Consequences** | Components must use the new token names. Product imagery must stay on `--color-image-surface`. A yellow outline means "selected"; hover uses grey outlines. Native controls follow `color-scheme: dark`. |
| **Affected areas** | `app/globals.css`, `app/layout.tsx`, all public pages, `components/Header.tsx`, `Footer.tsx`, `ProductCard.tsx`, `SeatFinder.tsx`, `ContactForm.tsx`, token names in unmounted `Experience.tsx`; docs per [Design system](design-system.md) |
| **Approver** | User request in the 2026-11-19 session |

## 2026-11-18 — Seating-focused UI and enquiry redesign

The user requested a complete redesign of the current VS Code repository and documentation, preserving the brand name/product imagery while replacing colours and UX. The implementation uses a plum/lavender furniture-catalogue direction, new layouts across all public pages, a work-setting finder, sorting and up-to-three-model comparison. [Design system](design-system.md) owns the visual contract; previous design entries below are historical.

The existing forms could not deliver enquiries. The new shared form prepares an email with review, mailto and copy/select fallback, using the existing repository email. It does not report receipt or silently map new fields into the logging-only API. That endpoint remains unchanged and public. Contact ownership and automatic delivery are still unresolved business/integration dependencies.

Company/services became Server Components after removing navigation/hover handlers. Quote became a request-rendered server shell to validate selected model slugs. No dependency, config, route, image file or hosting change was introduced. No fabricated product angles or certification/warranty promises were added. [Testing](testing-and-validation.md) records successful build checks and the browser-access limitation.

## 2026-11-07 — Searchable catalogue and static product details

The user authorized a modern UI, clearer product information, three-image galleries, calling and search discoverability. Home/catalogue/detail content now uses server components with focused client controls. Product records moved into one local catalogue module because home cards, listings, detail metadata and sitemap need the same identifiers. No service/data fetching layer or new package was added.

Native IntersectionObserver/Web Animations provides scroll motion with reduced-motion handling. Each gallery supports three real photos but currently has only one supplied asset; missing photos are labeled, not synthesized. Unknown product facts and existing contact ownership remain explicitly unverified. Metadata describes known content without fabricated offers/reviews. This is a local repository update; no deployment was requested or performed.

## 2026-10-09 — Modern Navbar Redesign & Direct Phone Call Integration

| Field | Value |
|---|---|
| **Status** | Accepted |
| **Problem** | The navigation bar used an older, plain design without active page states or direct call access, and mobile users needed an animated, accessible way to quickly call sales/inquiries. |
| **Decision** | Modernised `Header.tsx` with glassmorphic styling, pill navigation with active route detection (`usePathname`), smooth harmonic phone ring & pulse animations, a smooth morphing hamburger icon, and direct `tel:` links opening the user's phone app. |

| **Reasoning** | Keeps the UI sleek, modern, and high-converting while seamlessly triggering native phone dialers on mobile devices. |
| **Affected areas** | `components/Header.tsx`, `app/globals.css` |
| **Approver** | Selvaganapathi (repository owner) |
