# Routes and features

All implemented routes are public. All pages use [app/layout.tsx](../../app/layout.tsx), hence the shared Header/Footer. There are no administrative or authenticated areas.

| URL | Source / default export | Rendering and feature |
|---|---|---|
| `/` | [app/page.tsx](../../app/page.tsx) · Home | Server page; local-image hero, category links, featured product links and services CTA |
| `/company` | [app/company/page.tsx](../../app/company/page.tsx) · Company | Client entry, static; mission, badges, quote CTA; TEAM/MILESTONES unrendered |
| `/products` | [app/products/page.tsx](../../app/products/page.tsx) · Products | Server hero/metadata + Suspense catalogue; search, grid/table view, six filters, eight items/page |
| `/products/[slug]` | [detail page](../../app/products/[slug]/page.tsx) | 32 statically generated product pages; gallery, facts table, call action, related products; unknown slugs return 404 |
| `/services` | [app/services/page.tsx](../../app/services/page.tsx) · Services | Client entry, static; six services, four-step process, quote CTA |
| `/quote` | [app/quote/page.tsx](../../app/quote/page.tsx) · Quote | Client entry, static; controlled form → local success |
| `/contact` | [app/contact/page.tsx](../../app/contact/page.tsx) · ContactPage | Server page, static; mounts ContactForm |
| `/about` | [app/about/page.tsx](../../app/about/page.tsx) · AboutPage | Server page, static; generic placeholder content |
| `/api/contact` | [app/api/contact/route.ts](../../app/api/contact/route.ts) · POST | Dynamic handler; only explicit method is POST; [contract](data-flow.md) |
| `/sitemap.xml` | [app/sitemap.ts](../../app/sitemap.ts) · sitemap | Production-domain marketing and all 32 product URLs |

`/robots.txt` is generated by [app/robots.ts](../../app/robots.ts), allows public pages, blocks `/api/` and references the production sitemap.

The successful alternate Webpack build also lists framework `/_not-found`. `app/favicon.ico` is an asset, not a marketing page. See [Testing](testing-and-validation.md) for observed build output.

## Navigation and query contract

Header links to home/logo, company, products, services, quote and a `tel:` URI. Footer links to all five categories, company, services, products and contact, plus telephone/email links. Decorative social/legal labels were removed; `/about` remains a separate unlinked stub.

Home category links preserve `/products?type=…`. Catalogue also accepts legacy `category`; exact query semantics are in [Data flow](data-flow.md). Product cards use native links to unique detail routes, including distinct slugs for the two training-chair variants.

## Metadata and crawling

Root metadata uses `https://nwsworkspace.com`, shared OpenGraph/Twitter defaults and an Organization JSON-LD entity. Home/catalogue export route-specific metadata and canonicals. Detail routes export unique titles, descriptions, canonicals and social images; visible facts are also represented by Product and BreadcrumbList JSON-LD. Catalogue ItemList and its server-rendered fallback link all 32 products. Contact/about retain their metadata; company/services/quote inherit the root defaults.

The sitemap includes home, company, products, services, contact, quote and all products. The generic about stub is intentionally omitted. No fabricated modification dates, prices, stock, reviews, warranties or rich-result eligibility are emitted. Product markup lacks offers/reviews because those facts are unavailable; it is descriptive structured data, not a promise of Google product rich results. Public crawl permission and readable content support discovery, but indexing/AI inclusion and deployed CDN policy remain unverified.

## Modification checks

For an authorized new route, start with the relevant local framework guide; reuse root shell; choose server/client ownership deliberately; inspect Header/Footer only if navigation changes are requested. Verify metadata/sitemap inclusion intentionally. For catalogue changes also inspect home category links. For forms follow [Data flow](data-flow.md) and [Security](security.md). Update this map when routes or metadata behavior change.
